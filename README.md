# River Strike — النشر من GitHub إلى Cloudflare

هذه حزمة مستقلة للنشر اليدوي. تضم اللعبة نفسها، والتحكّم بإمالة الهاتف واللمس، والدعوات، ولوحة الترتيب، والمحاولات غير المحدودة مع احتساب أفضل نتيجة فقط. لا تحتاج إلى ربط ChatGPT بـ GitHub لتنفيذ الخطوات التالية.

## 1. رفع الملفات إلى GitHub

1. فك ضغط `River-Strike-GitHub-Cloudflare.zip` على الكمبيوتر.
2. سجّل الدخول إلى https://github.com ثم اختر **New repository**.
3. سمِّ المستودع `river-strike-template`، واختر **Public** ليعمل مسار زر النشر. هذا يجعل مصدر اللعبة ظاهرًا للعامة؛ الحزمة لا تحتوي على كلمات مرور أو مفاتيح أو نتائج لاعبين.
4. أنشئ المستودع، ثم اختر **uploading an existing file** أو **Add file → Upload files**.
5. اسحب محتويات المجلد المفكوك كلها إلى صفحة الرفع. ارفع الملفات والمجلدات، وليس ملف ZIP نفسه أو المجلد الخارجي. يجب أن ترى `package.json` و`wrangler.jsonc` و`worker.ts` مباشرة في جذر المستودع، ومعها المجلدات `public` و`app` و`drizzle` و`tests`.
6. اضغط **Commit changes**.

## 2. نشر اللعبة

1. أنشئ حسابًا أو سجّل الدخول في https://dash.cloudflare.com/ . أنت تنفذ تسجيل الدخول والموافقات من حسابك.
2. انسخ عنوان مستودع GitHub الذي أنشأته.
3. افتح العنوان التالي بعد استبدال `YOUR_GITHUB_USERNAME` باسم حسابك الحقيقي:

   `https://deploy.workers.cloudflare.com/?url=https://github.com/YOUR_GITHUB_USERNAME/river-strike-template`

4. في شاشة Cloudflare، اربط حساب GitHub وامنح الوصول إلى المستودع المطلوب. مسار **Deploy to Cloudflare** ينسخ القالب إلى مستودع جديد في حسابك؛ سمِّ نسخة التشغيل `river-strike-live`، واسم اللعبة/Worker `river-strike` أو اسمًا متاحًا تختاره.
5. احتفظ بقاعدة البيانات المطلوبة باسم `river-strike-scores` أو باسم آخر تقترحه الشاشة. ينشئ مسار زر النشر قاعدة D1 ويستبدل معرّفها التجريبي تلقائيًا.
6. اترك **Build command** فارغًا إن ظهر. اجعل **Deploy command** هو `npm run deploy`. ينشئ هذا الأمر جداول النتائج ثم ينشر اللعبة. إذا ظهر **Root directory** فاتركه جذر المستودع `/`.
7. راجع أي رسوم أو شروط تظهر في حسابك ثم اضغط **Deploy**. تتوقف حدود الاستخدام والتكلفة على خطة Cloudflare؛ الحزمة لا تختار ترقية مدفوعة تلقائيًا.
8. بعد نجاح النشر، افتح رابط HTTPS الذي تعرضه Cloudflare. يكون عادةً على نطاق `workers.dev`. هذا هو رابط اللعب، وليس رابط GitHub.

معرّف قاعدة البيانات في `wrangler.jsonc` قيمة تجريبية مقصودة لمسار **Deploy to Cloudflare**. لا تستخدم رفع ملفات ثابتة أو نشر Worker عاديًا بهذه القيمة. إذا اخترت الربط التقليدي بمستودع قائم بدل زر النشر، فأنشئ قاعدة D1 أولًا، وضع معرّفها الحقيقي مكان القيمة التجريبية، ثم استخدم `npm run deploy` في إعدادات النشر.

## 3. دعوة الأصدقاء والتحقق

افتح رابط اللعبة، واكتب اسمك واسم التحدّي، واختر الصعوبة، ثم اضغط **إنشاء رابط دعوة**. استخدم **دعوة عبر واتساب** أو **نسخ الرابط**. افتح الدعوة من جهاز آخر واسم مختلف للتأكد من أن الطرفين يريان لوحة الترتيب نفسها بعد انتهاء المحاولات.

كل لاعب يستطيع المحاولة بلا حد عددي، وتحتفظ اللوحة بأعلى نتيجة له. مدة المحاولة ثلاث دقائق كحد أقصى، ولكل لاعب ثلاث طائرات. السجل مرتبط بالمتصفح؛ حذف بيانات الموقع أو تغيير المتصفح قد ينشئ لاعبًا جديدًا. من يصله رابط التحدّي يستطيع الانضمام ورؤية الأسماء والنتائج.

على الهاتف افتح رابط HTTPS في متصفح الهاتف، وفعّل الإمالة واسمح بالحركة عند طلبها. تتوفر أزرار لمس إذا لم يدعم الجهاز المستشعرات. لم يتم التحقق على هاتف فعلي ضمن جلسة التطوير.

## إذا حدث خطأ

- عدم العثور على `package.json`: الملفات مرفوعة داخل مجلد إضافي؛ يجب أن تكون في جذر المستودع.
- خطأ في قاعدة البيانات: تأكد أنك تستخدم رابط **Deploy to Cloudflare** أعلاه، وأنك لم تغيّر اسم الربط `DB`. لا تُعد نشر القيمة التجريبية يدويًا على قاعدة موجودة.
- خطأ أثناء النشر: انسخ رسالة الخطأ من سجل النشر أو التقط صورة لها. لا ترسل كلمات مرور أو رموز وصول.
- تجنّب فتح HTML مباشرة أو استخدام GitHub Pages للنسخة التنافسية: الخادم وقاعدة البيانات ضروريان لمشاركة النتائج.

## حالة التحقق

نجحت اختبارات الخادم للترتيب والمحاولات المتكررة على قاعدة SQLite محلية، وفحص Wrangler للنشر التجريبي دون رفع (dry-run)، واختبارات توجيه رابط الدعوة وصفحة اللعبة وطلبات النتائج. حزمة النشر مستقلة عن مشروع Sites. النشر الفعلي وإنشاء الموارد في حساب Cloudflare يحتاجان تنفيذ الخطوات أعلاه؛ لا يوجد رابط منشور لهذه الحزمة بعد.
